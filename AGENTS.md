# Робота з Novelka

## Почати тут

- Прочитай `doc/README.md` і сторінку, що стосується задачі.
- Карта коду: `doc/architecture.md`; поведінка перекладу: `doc/pipeline-and-data.md`.
- Запуск і конфігурація: `doc/cli.md`; перевірки та обмеження: `doc/development.md`.
- Перед змінами перевір Git diff. Не перезаписуй незакомічені зміни користувача.

## Стиль і межі

- Java 25; відступ — 4 пробіли, Tab вставляє пробіли. Дотримуйся `.editorconfig`.
- Окремий файл для кожного класу, record та інтерфейсу. Не створюй вкладені типи.
- Обирай пакети за відповідальністю. CLI залежить від core; core не залежить від Picocli.
- Веб API живе в server (Spring Boot), React — у frontend; усе в одному репозиторії.
- Вебверсія поки лише читає готові переклади. У браузер не передавай ключі, AI-контекст чи JDBC-параметри.
- Зміни UI перевіряй через npm --prefix frontend run build та браузерні тести; правила — doc/web.md.
- Зміни контрактів CLI, конфігурації чи збереження супроводжуй оновленням відповідної документації.

## Дані та витрати

- Аліас перетворюється на канонічний ID до взяття lock і викликів pipeline.
- Не обходь блокування, версіонування, контроль бюджету й захист від повтору uncertain-викликів.
- Перенесення record-класів не повинно змінювати JSON-поля або хеші наявних даних.
- Семантику застосованих SQL-міграцій не змінюй. Для нової схеми додай наступну міграцію
  та явно зареєструй її в `MigrationRunner.LATEST_VERSION`.
- Не друкуй і не додавай у Git локальні env-файли або API-ключі.
- Звичайна перевірка коду не потребує платних OpenRouter-викликів.

## Завершення зміни

- Запусти `./gradlew test`; для збереження/міграцій — також `:core:integrationTest`.
- Зміни launcher перевіряй через `LauncherTest` / `WebLauncherTest` і `sh -n novelka novelka-web`.
- Зміни API перевіряй через `:server:integrationTest` (тимчасовий PostgreSQL, реальний HTTP).
- Production-конфігурація описана в `doc/deployment.md`; `.env.production` і SSH-ключі ніколи не коміть.
- Запусти `git diff --check`. Не заявляй успіх тестів, які не запускались або не пройшли.
- Збій `initdb` сам по собі не доводить проблему shared memory: прочитай stderr.
