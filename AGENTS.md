# Робота з Новелкою

- Почни з `AGENTS.md` і короткого знімка відкритих задач: `bash doc/prompts/board.sh`.
  Після вибору задачі читай її опис, потрібні розділи `doc/plan.md` і рішення власника,
  а `doc/brief.md` та інші специфікації — лише в частині, потрібній для цієї задачі.
- Проєкт пишеться з нуля. Документи попередньої версії можна читати як специфікацію
  поведінки й досвід, якщо її копія доступна; код звідти не копіюємо.
- У промпті задачі вкажи `Складність: мала | середня | архітектурна` (одне значення).
  Мала — локальна зміна з чіткими вимогами без зміни архітектури, прав доступу чи схеми БД:
  виконуй одразу в погодженому обсязі, без окремого плану й очікування «так».
  Середня й архітектурна — спершу погоджений власником план, потім код.
  Типовий запуск через Claude Code: мала — sonnet/medium, середня — sonnet/high;
  архітектурна — opus/high вручну в окремій сесії. Налаштування — `doc/prompts/engines.conf`.
  Якщо обсяг виріс за межі малої задачі, переглянь складність і погодь план.
- Локальна сесія — на VPS; хмарна — в окремому середовищі. Доступи перевіряй,
  не припускай їх наявності; робоче оточення не використовуй як тестову базу.
- Стек: Java + Spring Boot + jOOQ + Flyway + PostgreSQL; React + TypeScript (mobile-first).
- Інтерфейс і тексти для користувачів — українською.
- Репозиторій — `github.com/panrid/novelka` (публічний). Push у `main` запускає тести й деплой
  на `https://novelka.in.ua`, тож пушимо лише зелене. Один коміт на завершену задачу.
- Не комітити секрети, `.env`-файли, ключі API й SSH-ключі. Локальні ключі — у `.env.local`
  (його читає конфігурація `backend` у `.claude/launch.json`).
- Не заявляти успіх тестів, які не запускались або не пройшли.
- Задачі — на дошці https://github.com/users/panrid/projects/2 (етапи — задачі з позначкою
  «етап», пункти — під-задачі; стани: Беклог · Захолоджено · До роботи · У роботі · Готово).
  Стани змінює лише диспетчер із погодженням власника: беручи задачу — «У роботі»,
  після зеленого деплою — «Готово». Виконавець/launcher станів не змінює.
  У коміті — `Closes #N`. Нова
  задача від власника — нова задача на дошці (і в `doc/plan.md`, якщо це частина етапу).
  «Захолоджено» не пропонувати, доки власник сам не поверне.
  Сесія-диспетчер, що веде дошку й пише промпти для задач, — `doc/prompts/dispatcher.md`.
- Launcher типово відкриває PR навіть для власника; `--push-main` — лише за його явною
  вказівкою. Малі задачі запускаються одразу; середні — після плану й «так» власника.
- Не власник репозиторію? Працюй у своїй гілці чи форку й відкривай pull request — у `main`
  пушить лише власник. Як запустити проєкт і з чого почати — `doc/contributing.md`.
