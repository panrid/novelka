# Перевірка рефакторингу — 2026-09-20

[До змісту](README.md) · [Подальші зміни](development.md#межі-які-ще-потребують-роботи)

## Висновок

Виділення top-level команд і моделей покращило навігацію й прибрало вкладені типи.
JSON-поля моделей збережені, отже саме перенесення класів не потребувало міграції даних.
Частина прикладної логіки та SQL усе ще знаходиться в CLI; Store і OpenRouter
залишаються великими класами. Рефакторинг є корисним проміжним етапом.

Перевірка виконувалася поверх уже наявних незакомічених змін форматування.
Java-відступи у 4 пробіли збережено; додано EditorConfig.
SQL-міграції відформатовано без зміни послідовності непробільних символів.

## Виявлено й виправлено

| Проблема | Наслідок | Виправлення |
|---|---|---|
| Launcher запускав Gradle з поточного каталогу | Збірка з іншої директорії не знаходила проєкт | Явний -p ROOT, збереження cwd для файлів |
| Ручна перевірка mtime порівнювала джерела зі start script | Пропуск видалених файлів і неповний облік inputs; повторні перевірки за старим timestamp | Інкрементальне installDist на кожний запуск |
| Явно заданий відсутній env-файл ігнорувався | Можливий запуск з неочікуваними налаштуваннями | Помилка до збірки й запуску |
| Відносний env-файл передавався shell dot без нормалізації шляху | Залежність від пошуку PATH | Абсолютний шлях від cwd |
| import зберігав метадані до перевірки діапазону/конфлікту аліаса | Часткові записи після невдалого виклику | Рання валідація, транзакція metadata + alias |
| Новий ID міг перекрити раніше створений аліас | Та сама команда могла обрати іншу новелу | Перевірка конфлікту також при save(Novel) |
| Два процеси могли одночасно пройти перевірку аліаса | Неочікувана unique-помилка навіть для ідемпотентного add | Спільний transaction lock для ID/alias |
| Помилка міграції в конструкторі Store залишала Connection відкритим | Витік JDBC-з'єднання | Закриття з'єднання при невдалому конструюванні |
| Документація обіцяла «останню завершену» версію та автоматичні наступні міграції | Хибні очікування експорту й V3 | Опис відповідно до SQL та Store.migrate |

## Докази й межі перевірки

- LauncherTest перевіряє іншу cwd, пробіли в шляхах/аргументах,
  .env.local та явний env-файл, відсутній env, відмову запуску після помилки збірки.
- PipelineIntegrationTest перевіряє регістр аліасів, конфлікти в обох напрямках,
  повторне й конкурентне додавання, rollback metadata + alias, оновлення V1 → V2
  зі збереженням метаданих та повторне відкриття без повторного виконання міграції.
- Наявні тести перевіряють pipeline, збереження ревізій, відновлення,
  словник, HTTP-контракти, бюджет і експорт.
- Повний набір test та core:integrationTest пройшов у свіжому процесі
  з --no-daemon; installDist теж успішний.
- Причину попереднього збою embedded PostgreSQL підтверджено stderr:
  shmget — Operation not permitted у старому daemon. Це не помилка SQL-міграції.

Реальний Syosetu та платний OpenRouter під час цього рев'ю не викликались.
Літературна якість перекладу не оцінювалася. Робоча Docker-база не використовувалась
для тестових записів; інтеграційні тести працювали у тимчасових embedded-базах.

Подальші архітектурні зміни та відомі обмеження — у [development.md](development.md).
