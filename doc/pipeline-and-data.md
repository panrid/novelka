# Переклад, дані та відновлення

[До змісту](README.md) · [Архітектура](architecture.md) · [CLI](cli.md)

## Оригінал і сегменти

Номер глави — позиція епізоду джерела, починаючи з 1. Назва «0000 Пролог» не робить
номер глави нульовим. HTML перетворюється на heading, paragraph, preface, afterword
і separator. Ruby-читання зберігаються у тексті. Оригінальні блоки є основою контролю повноти.

`sourceHash = SHA-256(Json.write(chapter.blocks()))`. Зміна URL або rawHtml сама по собі
не змінює цей хеш. Для стабільності Json сортує ключі Map; поля моделей і порядок блоків
також важливі. Хешування рядка промпту включає його JSON-серіалізацію.

`Segments.split` групує цілі блоки в межах NOVELKA_SEGMENT_CHARS, типово 1500.
Це довжина Java String, не токени. Окремий завеликий абзац не розрізається:
операція завершується помилкою з порадою збільшити межу.

## Одна глава від початку до кінця

1. TranslateCommand розпізнає аліас, бере lock новели й завантажує відсутній оригінал.
2. Pipeline.create повертає останній Work або створює нову ревізію та job_metrics.
3. Для кожного сегмента analyze пропонує записи словника.
4. Коректні нові сутності додаються; конфліктні й некоректні пропозиції лишаються для перегляду.
5. Translate створює draft; повна proofread створює revised і короткий summary.
6. Work стає complete. Експорт виконується окремою командою.

| Segment.state | Що вже збережено | Наступна дія |
|---|---|---|
| pending | source | analyze |
| analyzed | результати аналізу й оновлення словника у транзакції | translate |
| translated | draft | proofread |
| complete | revised і context/summary | наступний сегмент |

Work має стани pending, running, complete, needs-review. running не означає,
що процес зараз живий: це збережений незавершений стан. Окремого heartbeat або черги немає.
Work.summary — останній summary сегмента, не гарантований повний переказ глави.

Передається короткий summary попередньої завершеної глави або попереднього сегмента,
а також останні два оригінальні блоки сусіднього сегмента. Старі глави автоматично
не перекладаються за гроші заради отримання контексту.

## Версії та експорт

- translate без force використовує останню ревізію; complete повертається без нових AI-викликів.
- Якщо оригінал змінився, create вимагає force.
- translate --force завжди створює новий Work: це може повторно витратити кошти.
- proofread створює нову ревізію з revised як draft, або зі старим draft, якщо revised немає.
  Кожен сегмент мусить уже мати draft; аналіз і переклад не повторюються.
- Store.completed обирає **останню ревізію кожної глави**, потім перевіряє complete
  і відповідність sourceHash. Якщо остання ревізія незавершена, старіша завершена не експортується.

Експорт може пропускати незавершені глави та створювати книгу з прогалинами в нумерації.
BookExporter пише тимчасовий файл поряд із результатом і потім замінює цільовий файл;
вже наявний експорт перезаписується.

## Словник

Entry містить key, kind, japanese, reading, ukrainian, aliases, gender, facts,
certainty, sourceChapter, manual. Невідоме читання/стать не треба вигадувати.
Пропозиція моделі не повинна перезаписувати наявну сутність.
Ручний JSON імпортується за key і отримує manual=true.

Dictionary.select добирає згадані й пов'язані записи до 3000 токенів.
dictionary_search повертає до 1500 токенів за звернення, максимум 6 звернень
і 4 HTTP-раунди на етап сегмента. Це локальний tool call, а не webhook.
Повний словник читається з БД у пам'ять, але не надсилається весь у кожному запиті.

Зміна існуючого запису шукає його key у збережених контекстах AI-викликів
(включно з відповідями tool) і позначає залежні Work як needs-review.
Додавання нової сутності саме по собі не робить попередні глави застарілими.
UI погодження пропозицій ще немає; є перегляд --proposals і ручний JSON-імпорт.

## Запити та гроші

AiClient отримує верхню межу **сукупної витрати конкретного Work**.
CLI --budget-usd означає бюджет **нових викликів поточного запуску**;
TranslateCommand і ResumeCommand додають до нього вже враховану витрату Work.
Для діапазону бюджет спільний, а не на кожну главу. 0 означає відсутність стелі.

Перед HTTP зберігається pending AiCall із резервом:

`(UTF-8 bytes(request) × inputRate + 8192 × outputRate) / 1_000_000`

Це консервативна оцінка, не точний токенізатор моделі. Фактична ціна береться з usage.cost.
Store.spent сумує COALESCE(actual_usd, estimated_usd), включно з невідомими результатами;
NULL не означає безкоштовний виклик. Поточний target_usd — $0.10 на 5000 токенів
оригіналу, історично обраний орієнтир, а не гарантія витрати чи актуальний тариф.

| AiCall.state | Поведінка |
|---|---|
| pending | Записано перед HTTP; після падіння вважається потенційно оплаченим |
| complete | Успішна HTTP-відповідь збережена; це ще не означає валідний переклад |
| failed | Зокрема HTTP 400/401/402/429; 429 має до трьох спроб |
| uncertain | Тайм-аут, транспортна помилка, нечитабельний JSON або невизначена відповідь |
| retry-authorized | Користувач дозволив нову спробу через resume --retry-uncertain |

Відповідь зберігається до її застосування. Для того самого job/stage/segment і контексту
complete-відповідь використовується повторно. Зміна моделі, промпту чи словника
може змінити контекст і спричинити новий запит. Некоректна відповідь може вже бути оплачена.
Strict JSON Schema контролює наявність усіх блоків, а не смислову точність речень.

## SQL і блокування

Таблиці описані у [короткому огляді](README.md#зберігання-даних).
Оригінали мають chapter_versions; словник — glossary_versions; переклади — jobs.revision.
Дані моделей зберігаються як jsonb, а поля для пошуку винесені в колонки.
FK є не для всіх історичних таблиць; довільне видалення novels не є підтримуваним очищенням.

Store володіє одним JDBC Connection і не призначений для спільного використання потоками.
transaction при вкладеному виклику використовує зовнішню транзакцію, без savepoint.
Помилки вкладених операцій треба пропускати до зовнішнього rollback.

- 728615 — transaction advisory lock міграцій.
- 728616 — transaction advisory lock реєстрації ID та аліасів.
- hashtext(canonicalNovelId) — session advisory lock CLI-операцій над новелою.

Міграції V1 і V2 виконуються в транзакції. Автоматичного пошуку довільної V3 немає:
верхню версію потрібно змінити в Store.migrate. Парсер ділить SQL за `;`,
тому зараз не підтримує процедурні блоки чи рядки із крапкою з комою.
