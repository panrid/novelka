# Документація Novelka

Novelka — застосунок із CLI та вебчиталкою для перекладу японських вебновел українською. Поточна версія імпортує метадані й глави,
веде словник новели, виконує аналіз, переклад і ШІ-вичитку через OpenRouter, зберігає версії та витрати в PostgreSQL і
експортує готовий текст у HTML або EPUB.

## Структура проєкту

```text
novelka/
├── core/                 # Моделі, процес перекладу, інтеграції та експорт
├── cli/                  # Команди Picocli
├── server/               # Spring Boot: API читалки та зібраний сайт
├── frontend/             # React + TypeScript + Vite
├── infra/compose.yaml    # Локальний PostgreSQL
├── examples/             # Приклад ручного словника
├── doc/                  # Документація коду
├── novelka               # Локальний скрипт запуску CLI
└── novelka-web           # Зібрати та запустити сайт
```

Це один репозиторій із трьома Java-модулями Gradle: core, cli та server.
CLI викликає процес перекладу; server надає API читання, акаунтів, правок і фонових перекладів через той самий core.
React-фронтенд має власний package.json і lockfile в frontend; Gradle пакує його
в серверний JAR. CLI працює окремо і не потребує запуску сайту.

## Процес перекладу

```text
Syosetu або локальний файл
          │
          ▼
  структуровані блоки
          │
          ▼
 аналіз словника ──► пропозиції нових фактів
          │
          ▼
      переклад
          │
          ▼
 повна ШІ-вичитка
          │
          ▼
 PostgreSQL ──► HTML / EPUB
```

Глава складається зі стабільних блоків `Block`: заголовка, абзаців, передмови, післямови або розділювачів сцени. Довга
глава ділиться між абзацами на сегменти. Типова межа — 1500 символів.

Кожен сегмент проходить стани `pending` → `analyzed` → `translated` → `complete`. Результат кожного етапу зберігається
одразу, тому після переривання робота продовжується з останньої контрольної точки. Завершене завдання отримує стан
`complete`; після зміни використаного запису словника воно може перейти в `needs-review`.

Переклад і вичитка повертають суворо структурований JSON: кожен ID оригінального блока мусить мати рівно один результат.
Це запобігає непомітному пропуску або об'єднанню абзаців. Така перевірка гарантує структурну повноту, але не гарантує
літературну чи смислову якість.

## Основні класи

| Клас                | Відповідальність                                                                        |
|---------------------|-----------------------------------------------------------------------------------------|
| `core.model`        | Окремі незмінні моделі новели, глави, блока, словника, сегмента, завдання й виклику ШІ. |
| `Syosetu`           | Перевіряє URL, читає метадані через Syosetu API та перетворює HTML глави на блоки.      |
| `PlainText`         | Імпортує наданий користувачем UTF-8 текст; перший непорожній рядок стає заголовком.     |
| `Segments`          | Ділить главу на сегменти й перевіряє відповідність ID та типів блоків.                  |
| `Dictionary`        | Валідує словник, знаходить згадані та пов'язані записи й обмежує контекст токенами.     |
| `Pipeline`          | Оркеструє аналіз, переклад, вичитку, контрольні точки та версії результату.             |
| `OpenRouter`        | Формує запити, викликає моделі, обслуговує пошук у словнику та журналює використання.   |
| `DatabaseSession`   | Створює спільне JDBC-з'єднання, репозиторії та сервіс словника; керує їхнім життєвим циклом. |
| `core.repository`   | SQL новел, глав, завдань, словника й журналу AI-викликів у п'яти окремих класах. |
| `GlossaryService`   | Атомарно оновлює словник та позначає залежні переклади як needs-review. |
| `MigrationRunner`   | Застосовує зареєстровані SQL-міграції в транзакції. |
| `BookExporter`      | Створює HTML та EPUB лише з актуальних завершених глав.                                 |
| `Tokens`            | Рахує токени оригіналу й контексту за `o200k_base`.                                     |
| `Novelka`           | Коренева Picocli-команда і точка входу.                                                 |
| `cli.command`       | Окремий клас для кожної користувацької команди.                                         |
| `cli.command.alias` | Додавання, перегляд і видалення аліасів новел.                                          |
| `cli.config`        | Створення сховища та перекладацького pipeline з конфігурації.                           |
| `cli.support`       | Виведення JSON і перевірка діапазонів глав.                                             |

Інструкції для моделей лежать у `core/src/main/resources/prompts`: окремо для аналізу, перекладу та вичитки. Їхній хеш
входить у версію запиту, тому зміна інструкції відрізняє новий результат від раніше збереженого.

## Словник новели

`Glossary` має незалежну історію для кожної новели. Запис `Entry` містить:

- японський ключ і написання;
- читання імені, якщо воно підтверджене;
- канонічний український відповідник і псевдоніми;
- тип сутності, стать, факти та главу-джерело;
- певність: `confirmed`, `assumed` або `unknown`;
- ознаку ручного запису.

Повний словник не додається до кожного запиту. Спочатку код добирає згадані імена, псевдоніми й терміни разом із
пов'язаними записами в межах 3000 токенів. Модель може додатково викликати `dictionary_search`, який повертає до 1500
токенів.

Новий коректний запис може автоматично потрапити до словника. Зміна вже наявного факту зберігається як пропозиція для
ручної перевірки. Некоректна пропозиція теж зберігається з причиною відхилення, але не змінює канонічний словник і не
зупиняє переклад. Ручні записи мають пріоритет.

## Зберігання даних

PostgreSQL зберігає предметні дані переважно у `jsonb`, а поля для пошуку та зв'язків — окремими колонками.

| Таблиця              | Вміст                                                                                 |
|----------------------|---------------------------------------------------------------------------------------|
| `novels`             | Поточні метадані новел.                                                               |
| `novel_aliases`      | Короткі користувацькі імена, які посилаються на канонічні ID новел.                   |
| `chapters`           | Поточна версія оригіналу кожної глави.                                                |
| `chapter_versions`   | Історія оригіналів за SHA-256 їхніх блоків.                                           |
| `glossaries`         | Поточний словник новели.                                                              |
| `glossary_versions`  | Історія словника.                                                                     |
| `glossary_proposals` | Автоматичні й відхилені пропозиції змін.                                              |
| `jobs`               | Версії перекладу, сегменти та їхні стани.                                             |
| `job_metrics`        | Токени оригіналу, токенізатор і цільова ціна.                                         |
| `ai_calls`           | Запит, відповідь, модель, провайдер, токени, оцінена й фактична ціна кожного виклику. |

Перед обробкою новели береться advisory lock PostgreSQL за канонічним ID.
Події сайту зберігаються в `notifications`, індивідуальне прочитання — в `notification_reads`.
Відхилення однакових пропозицій словника зберігаються в `glossary_proposal_dismissals`.
Під час створення DatabaseSession клас MigrationRunner послідовно застосовує зареєстровані V1.sql–V15.sql;
виконані версії фіксуються у schema_versions. Для наступної міграції потрібно
додати файл і змінити верхню версію в MigrationRunner.LATEST_VERSION; автосканування файлів немає.

## Витрати та відновлення

Перед HTTP-запитом створюється запис `ai_calls` зі станом `pending` і консервативною оцінкою вартості. Після відповіді
зберігаються її ID, повний JSON, провайдер, тривалість, токени й фактична ціна, якщо API її повернуло.

Успішна відповідь може бути повторно використана після збою програми. Якщо результат мережевого запиту невідомий, він
отримує стан `uncertain` і не повторюється автоматично, бо попередній виклик міг уже бути оплачений. Свідомий повтор
дозволяє `resume --retry-uncertain`.

`--budget-usd` обмежує нові запити поточного запуску. Окремо OpenRouter-ключ може мати серверний ліміт витрат. Значення
`actual_usd = NULL` означає невідому вартість, а не нуль.

## CLI

```sh
./novelka init
./novelka import URL [--alias NAME] [--title-uk TITLE] [--chapter N | --chapters A-B]
./novelka import-text NOVEL_ID --chapter N --file FILE
./novelka chapters NOVEL_ID
./novelka translate NOVEL_ID (--chapter N | --chapters A-B) [--budget-usd USD] [--force]
./novelka resume JOB_ID [--retry-uncertain]
./novelka proofread NOVEL_ID --chapter N
./novelka status [NOVEL_ID]
./novelka glossary NOVEL_ID [--file FILE | --proposals]
./novelka export NOVEL_ID --format html|epub --output FILE
./novelka costs [NOVEL_ID] [--details]
./novelka alias add NOVEL_ID ALIAS
./novelka alias list [NOVEL_ID]
./novelka alias remove ALIAS
```

`translate --force` створює нову версію перекладу. `proofread` також створює нову версію, використовуючи попередній
результат як чернетку. Експорт спершу бере останню ревізію кожної глави, а потім
перевіряє complete і відповідність оригіналу. Старішої завершеної ревізії замість
новішої незавершеної він не підставляє.

У параметрі `NOVEL_ID` можна передавати канонічний ID або аліас. Аліаси зберігаються в `novel_aliases`;
`import --alias NAME` створює аліас разом з імпортом. Кореневий скрипт сам перебудовує CLI після зміни коду і завантажує
`.env.local`.

Повна інструкція запуску й перелік змінних середовища наведені в кореневому `README.md`. Секретні файли `.env.local` та
`.env.translation.local` ігноруються Git; ключі не потрапляють до записів `ai_calls`.

## Тести

```sh
./gradlew test
./gradlew :core:liveSourceTest
./gradlew :core:integrationTest
```

- `test` перевіряє парсер, сегментацію, словник, pipeline, структуровані відповіді, mock HTTP, HTML та EPUB;
- `liveSourceTest` читає метадані й одну публічну главу Syosetu без викликів ШІ;
- `integrationTest` перевіряє реальний тимчасовий PostgreSQL і відновлення процесу з mock OpenRouter.

Жоден тест не виконує платні виклики моделей.

## Відомі обмеження

- Підтримується лише Syosetu та локальний текст.
- Лексичний пошук словника ще не має векторного індексу.
- Один абзац, довший за межу сегмента, потрібно обробити збільшенням `NOVELKA_SEGMENT_CHARS`.
- Автоматична вичитка все ще може пропускати смислові помилки, числа, суб'єкти й непослідовність стилю між сегментами.
- HTML/EPUB — готові файли; пропонування й погодження правок доступне в читалці на сайті.
