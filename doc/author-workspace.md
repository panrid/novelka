# Авторський простір і приватні публікації

Структуру й план погоджено власником 2026-10-28. Етап #328.
Інтерфейс та API реалізовано в #329–#331. Виправлення #337 / PR #338 випущено,
фактичне перенесення й звірку #332 завершено 2026-10-28. Сайт — джерело правди;
попереднє приватне сховище — знімок перенесення.

## Одне джерело правди

Після перевіреного перенесення робочі матеріали твору зберігає Новелка: людина
редагує їх у Студії, агент — через API з правами власника токена. Git використовується
для коду та експорту матеріалів. До звірки імпорту основним залишається поточне
приватне сховище. Двосторонню синхронізацію незалежних копій не робимо.

## Структура

У Студії твору: рукопис; світ і канон; план і хронологія; рішення й реткони;
ілюстрації та вкладення. Матеріали — документи з назвою, видом, текстом, посиланнями
на інші документи та історією змін. Для нотаток зберігаємо Markdown; рукопис
використовує наявний редактор глав і ревізії. Не дублюємо текст глав у нотатках.
Поточний стан роботи — окремий документ. Пошук повертає назви та короткі фрагменти,
читання документа — окремий запит, списки — сторінками.

## Приватність і права

Видимість публікації: «Публічна» або «Приватна». Новий авторський простір за
замовчуванням приватний. Наявні публікації зберігають поточний доступ; перемикання
власником явне. Перенесення матеріалів не змінює видимість уже опублікованих глав.

| Хто | Доступ |
|---|---|
| Власник команди | Усі матеріали, керування видимістю й запрошеними читачами |
| Команда твору | Робочі матеріали та глави; редагування й публікація за чинними ролями команди |
| Запрошений читач | Читання опублікованих глав приватної публікації та їхніх вкладень |
| Решта | Приватна публікація недоступна, зокрема за прямим посиланням |

Команда твору — чинна команда публікації, а не розробники сайту. Роль адміністратора
сама собою доступу до робочих матеріалів не дає. Запрошення прив’язане до акаунта:
власник додає зареєстрованого читача за ніком і може одразу відкликати доступ.
Самого знання адреси недостатньо. Поштові запрошення з реєстрацією не потрібні для
першої версії. Запрошення не надає права редагувати або читати канон, плани,
чернетки й історію робочих правок. Власник бачить список запрошених читачів.

Перевірки централізовані в AccessPolicy й застосовуються до кожного способу
отримання даних: сайт, API, експорт, вкладення, словник, коментарі, бібліотека,
пошук, профілі, стрічки, sitemap, сповіщення та вебхуки. Недоступна приватна
публікація повертає 404. Глобальні публічні списки її не показують.
Приватні файли віддаються через перевірку прав, без загальнодоступної адреси.
Відповіді з приватними даними не кешуються спільним кешем. Після відкликання
доступу нові запити відхиляються; уже отриманий людиною текст відкликати неможливо.

## Послідовність реалізації

1. **Приватні публікації.** Flyway: видимість публікації й таблиця дозволів читачів.
   AccessPolicy: читання, керування доступом. Студія: вибір видимості, список і
   додавання/видалення читачів за ніком. Захист усіх каналів читання, приватних
   вкладень і похідних даних; видимість враховувати до підрахунку та пагінації.
2. **Авторські матеріали.** Таблиці документів, посилань, ревізій і приватних
   вкладень. Список за видами, редактор, пошук, історія, відновлення версії.
   Конфлікт застарілої версії не затирає чужу правку. Без окремих серверів чи dev-стенда.
3. **API.** Списки та пошук із пагінацією, читання окремих документів, створення,
   правки з обов’язковою перевіркою версії, історія та експорт. Чинні токени й
   обмеження конкретним твором; доступ агента не ширший за доступ власника токена.
   Для економії контексту не віддавати весь рукопис у кожній відповіді.
4. **Перенесення.** Пробний імпорт із попереднім переглядом відповідності документів
   і посилань; повторний запуск не створює дублів. Звірити глави, нотатки, картинки,
   тексти та внутрішні посилання. Після перевірки зафіксувати Новелку основним
   сховищем, репозиторій — знімком для експорту. Не публікувати чернетки автоматично.

## Перевірка готовності

- Гість і сторонній акаунт не отримують приватних назв, текстів або файлів через
  жоден із перелічених каналів, у тому числі після зміни публічної видимості на приватну.
- Команда працює відповідно до ролей; запрошений читає дозволені опубліковані глави,
  але не робочі документи. Відкликання доступу перевірене сайтом і API.
- Конкурентні правки дають конфлікт із можливістю зберегти свою версію.
- Імпорт не змінює зміст матеріалів і не створює повторів; експорт дозволяє забрати
  рукопис і нотатки з вкладеннями.
- Backend: JUnit/Testcontainers для матриці доступу, ревізій та імпорту.
  Frontend: перевірки керування доступом, редактора й конфліктів; огляд на телефоні
  та комп’ютері. Перед випуском — backend:test, frontend check і зелений деплой.

## Межі першого випуску

Без спільного редагування одного абзацу в реальному часі, анонімних секретних
посилань і нового пошукового сервера. Резервне копіювання лишається окремою,
раніше відкладеною задачею. Історія ревізій не замінює резервну копію.

## Уточнення після перевірки (#337)

Робоча картинка має постійну прив’язку до авторського простору: видалення вкладення
не відкриває стару адресу. Картинка іншого простору не прикріплюється за її ID;
для перенесення потрібне окреме завантаження. Нові завантаження закриті до їх явного
використання у публікації. Оригінальні байти зберігаються окремо від варіантів для читання.

Редагування чинного документа та відновлення ревізії потребують очікуваної версії.
Пакетний імпорт не замінює змінений документ без поточної версії; незмінений повтор
не створює ревізій. Записи серіалізуються перед перевіркою версії.

`GET …/workspace/export` зберігає сумісний JSON-опис матеріалів.
`GET …/workspace/export.zip` містить документи Markdown, рукопис із ревізіями й
чернетками, реальні байти вкладень та контрольні суми SHA-256. Для давніх картинок,
оригінал яких раніше не зберігався, береться найбільший наявний варіант.

Сповіщення перевіряють чинний доступ при створенні, читанні та зовнішній доставці.
Офлайн-кеш не зберігає відповіді з приватними творами або робочими документами.

## Результат перевірки та перенесення

[Повний CI](https://github.com/panrid/novelka/actions/runs/40759854080) і
[деплой виправлень](https://github.com/panrid/novelka/actions/runs/40760747352) зелені.
Після випуску перенесено реальні матеріали: вміст документів звірено байт у байт
через API та експорт; оригінальні файли — за SHA-256. Перевірено пробний імпорт,
повтор із Idempotency-Key та повтор без ключа: дублів немає. Гостьові запити
до робочих вкладень відхиляються. Тексти та номери ревізій опублікованого рукопису
порівняно до й після перенесення — вони не змінилися. Інструкції джерела оновлено:
поточна робота ведеться на сайті, Git зберігає історичний знімок.

Приватні тексти, назви файлів, токени та звіти імпорту в цей публічний репозиторій
не включаються.
