# Як долучитися до Новелки (людині й її агентові)

Репозиторій публічний: `https://github.com/panrid/novelka`. Пушити в `main` може лише власник —
**push у `main` одразу запускає тести й деплой на https://novelka.in.ua**. Тож усі інші
працюють у своїй гілці (у форку або, якщо власник дав доступ, у цьому репозиторії) і
відкривають pull request; власник переглядає й зливає.

## 1. Що встановити

| Що | Версія | Навіщо |
|---|---|---|
| Git | будь-яка свіжа | код |
| JDK | 25 (наприклад, `sdk install java 25.0.4-amzn` через SDKMAN) | бекенд (Spring Boot, Gradle тягнеться сам через `./gradlew`) |
| Node.js з npm | 22.12 або новіший | фронтенд (React + Vite) |
| Docker Desktop | запущений | локальна база PostgreSQL і Mailpit; тести й генерація jOOQ (Testcontainers) |
| GitHub CLI `gh` | за бажанням | форк і pull request з терміналу |

Перевірка: `java -version` (25), `node -v` (≥ 22.12), `docker info` (без помилок).

## 2. Забрати код

```sh
gh repo fork panrid/novelka --clone      # або: git clone https://github.com/<ваш-нік>/novelka.git
cd novelka
npm --prefix frontend ci
```

## 3. Запустити локально

Два термінали:

```sh
./gradlew :backend:bootRun          # API на http://127.0.0.1:8080
npm --prefix frontend run dev       # сайт на http://127.0.0.1:5173 — відкривати цей
```

- Перший `bootRun` сам піднімає Docker-контейнери з `infra/compose.yaml`: PostgreSQL на
  `127.0.0.1:5433` і Mailpit на http://127.0.0.1:8025. Міграції бази застосовуються самі.
- Перший запуск довгий: Gradle качає залежності й генерує класи jOOQ (потрібен Docker).
- Листи сайту (підтвердження пошти, скидання пароля) нікуди не йдуть — їх видно в Mailpit.

### Акаунт власника сайту локально

Більшість Студії й автоперекладу відкриті лише власнику сайту. Щоб стати ним у своїй
локальній базі, перший раз запустіть бекенд так (будь-які свої значення):

```sh
NOVELKA_OWNER_NICK=owner NOVELKA_OWNER_EMAIL=me@example.test NOVELKA_OWNER_PASSWORD='довгий пароль' ./gradlew :backend:bootRun
```

Акаунт створюється вже підтвердженим, лише якщо власника ще немає. Далі запускайте без цих змінних.
Звичайний акаунт: http://127.0.0.1:5173/register і посилання з листа в Mailpit.

### Ключі (необов'язково)

Сайт працює й без них; без ключа OpenRouter лише не запускається автопереклад і малювання.
Свої ключі кладіть у `.env.local` у корені репозиторію — Git його ігнорує:

```sh
NOVELKA_OPENROUTER_KEY=sk-or-...        # ваш власний ключ OpenRouter, за ваші гроші
```

і запускайте бекенд з ним: `set -a; . ./.env.local; set +a; ./gradlew :backend:bootRun`
(так само робить конфігурація `backend` у `.claude/launch.json`). Інші змінні — у
[development.md](development.md#змінні-середовища-production). **Ніколи не комітьте ключі,
`.env`-файли, паролі.** Ключів і доступу до сайту власника у вас немає й не потрібно.

## 4. Перевірки перед pull request

```sh
./gradlew :backend:test             # бекенд: JUnit + Testcontainers (Docker має працювати)
npm --prefix frontend run check     # фронтенд: tsc, eslint, vitest
```

Або все разом: `./gradlew check`. У тестах модель і сайти-джерела підроблені — платних
викликів немає. Pull request — лише з зеленими перевірками; не пишіть, що тести пройшли,
якщо їх не запускали.

## 5. Робота з агентом (Claude Code та інші)

- Відкрийте агента в корені репозиторію. Правила проєкту — у [`AGENTS.md`](../AGENTS.md);
  `CLAUDE.md` підключає їх для Claude Code. Іншому агентові першою фразою скажіть прочитати
  `AGENTS.md`.
- Деякі пункти `AGENTS.md` стосуються лише власника: шлях `~/IdeaProjects/novelka-v1` є
  тільки на його машині, а замість push у `main` ви відкриваєте pull request.
- `.claude/launch.json` має дві конфігурації — `backend` і `frontend` — для перегляду сайту
  у вбудованому браузері агента.
- Добрий перший запит агентові:

  > Прочитай AGENTS.md, doc/brief.md і doc/contributing.md. Задача: <що зробити>. Спершу
  > покажи план і які файли зміниш; код — лише після мого «так». Працюй у гілці <назва>,
  > перед комітом запусти `./gradlew :backend:test` і `npm --prefix frontend run check`.

- Новий дизайн: [redesign/README.md](redesign/README.md) — запит власника, рішення й макет
  (полотно відкрите за посиланням). Реалізацію редизайну спершу погоджують із власником.

## 6. Правила, на яких найчастіше спотикаються

- **Код — після погодженого плану.** Нова можливість спершу описується (що, де, як виглядає) і
  погоджується з власником; так написано в `AGENTS.md`.
- **Інтерфейс і тексти — українською**, з правильними відмінками й без русизмів.
- **Міграції:** `backend/src/main/resources/db/migration/V{N}__опис.sql`, `N` — наступний
  вільний номер у `main` **на момент злиття**. Flyway не застосує меншу версію після більшої,
  тож перед pull request підтягніть `main` і перевірте `ls backend/src/main/resources/db/migration | sort -V | tail`.
  Уже злиту міграцію не змінюють — лише нову поверх.
- **Модулі бекенду** не лізуть у внутрішні пакети один одного (`ModularityTests`).
- **Один коміт — одна завершена задача**, повідомлення українською: що змінилось для людей.
- **Мобільна версія — головна**: перевіряйте на ширині 390 px, а Студію — і на ноутбуці.
