# Novelka / Новелка

Консольний клієнт для перекладу японських новел українською: Syosetu → аналіз словника → переклад → повна вичитка →
HTML / EPUB. Java 25, Gradle, PostgreSQL, OpenRouter. `core` містить прикладний процес; `cli` — Picocli-інтерфейс.
`server` — Spring Boot API та роздавання сайту; React + TypeScript лежить у `frontend`.
Вебверсія наразі містить каталог і читалку готових перекладів.

Короткий опис створеного коду, станів процесу та схеми даних: [документація розробника](doc/README.md).

## Запуск сайту

Потрібні JDK 25, Node.js 22.12+ з npm та запущений PostgreSQL.
З кореня репозиторію:

```sh
./novelka-web
```

Відкрийте [http://127.0.0.1:8080](http://127.0.0.1:8080).
Скрипт читає той самий `.env.local`, встановлює npm-залежності при першій збірці,
збирає React і сервер в один JAR та запускає його. Повторна збірка інкрементальна.
Інший порт: `./novelka-web --server.port=8081`. Зупинка — Ctrl+C.

Каталог читає наявні дані БД. Імпорт і переклад запускаються через CLI;
ключ OpenRouter для читання не потрібен. Докладніше: [фронтенд і API](doc/web.md).

## Швидкий старт CLI

Потрібні JDK 25, запущений Docker Engine / Docker Desktop та ключ OpenRouter. CLI не запускає вебсервер. Команди нижче
виконуються з кореня репозиторію.

```sh
test -e .env.local || cp .env.example .env.local
# Додайте OPENROUTER_API_KEY у .env.local
docker compose --env-file .env.local -f infra/compose.yaml up -d --wait
./gradlew test
./novelka init
./novelka import https://ncode.syosetu.com/n0022gd/ --alias water-magician --chapter 1
./novelka translate water-magician --chapter 1 --budget-usd 0.10
./novelka export water-magician --format html --output exports/book.html
```

Скрипт `./novelka` перевіряє інкрементальну збірку Gradle при кожному запуску:
незмінені задачі пропускаються, зміни та видалення файлів враховуються.
Він також завантажує `.env.local`. Інший файл можна вибрати так:
`NOVELKA_ENV_FILE=.env.translation.local ./novelka …`.
Відсутній явно заданий файл спричиняє помилку; файли не об'єднуються.
Докладні правила шляхів і пріоритетів — у [довіднику CLI](doc/cli.md).

`import` без діапазону зберігає лише метадані. Під час `translate` відсутні оригінали завантажуються автоматично.
Оновити вже збережений оригінал можна повторним `import` із главою або діапазоном. Адреса має бути
`https://ncode.syosetu.com/n…/`; сторінка `syosetu.com` є порталом, а тексти розташовані на `ncode.syosetu.com`.

```sh
./novelka translate n2267be --chapters 1-10
./novelka chapters n2267be
./novelka status n2267be
./novelka resume JOB_ID
./novelka proofread n2267be --chapter 1
./novelka costs n2267be
./novelka costs n2267be --details
./novelka --help
```

Замість технічного ID можна створити короткий аліас і використовувати його в командах, які приймають новелу
(resume приймає JOB_ID):

```sh
./novelka alias add n0022gd water
./novelka alias list
./novelka translate water --chapters 1-10
./novelka alias remove water
```

Аліас також можна додати одразу під час імпорту через `import URL --alias water`. Він нечутливий до регістру; дозволені
літери, цифри, `.`, `_` та `-`.

Готові глави повторно не перекладаються. `translate --force` створює нову версію. `proofread` створює окрему версію
редактури зі збереженням попередньої. Експорт перевіряє останню ревізію кожної глави:
вона має бути complete й відповідати поточному оригіналу. Якщо остання ревізія
незавершена, старіша завершена не підставляється. Неперекладені глави не домішуються до книги.

## Конфігурація

Параметри читаються зі змінних середовища. Скрипт запуску автоматично завантажує `.env.local`; приклад — `.env.example`.
Передані ззовні змінні можна перевизначити у вибраному env-файлі. Реальні ключі не зберігайте в Git.

| Змінна                                                            | Типове значення / призначення                               |
|-------------------------------------------------------------------|-------------------------------------------------------------|
| `OPENROUTER_API_KEY`                                              | Обов'язкова для платних команд                              |
| `NOVELKA_DB_URL`                                                  | `jdbc:postgresql://localhost:5432/novelka`                  |
| `NOVELKA_DB_USER`                                                 | `novelka`                                                   |
| `NOVELKA_DB_PASSWORD`                                             | `novelka`, також використовується Compose                   |
| `NOVELKA_MODEL`                                                   | `openai/gpt-4o-mini`; `--model` задає базову модель запуску |
| `NOVELKA_ANALYZE_MODEL`                                           | Окрема модель аналізу, інакше базова                        |
| `NOVELKA_TRANSLATE_MODEL`                                         | Окрема модель перекладу, інакше базова                      |
| `NOVELKA_PROOFREAD_MODEL`                                         | Окрема модель редактури, інакше базова                      |
| `NOVELKA_SEGMENT_CHARS`                                           | `1500`, межа сегмента по символах, між абзацами             |
| `NOVELKA_TARGET_USD_PER_5000`                                    | `0.10`, цільова оцінка всього pipeline на 5000 токенів      |
| `NOVELKA_ANALYZE_INPUT_USD_M`, `NOVELKA_ANALYZE_OUTPUT_USD_M`     | Ціна мільйона токенів моделі аналізу                        |
| `NOVELKA_TRANSLATE_INPUT_USD_M`, `NOVELKA_TRANSLATE_OUTPUT_USD_M` | Ціни моделі перекладу                                       |
| `NOVELKA_PROOFREAD_INPUT_USD_M`, `NOVELKA_PROOFREAD_OUTPUT_USD_M` | Ціни моделі вичитки                                         |

Для GPT-4o-mini початкові орієнтири — $0.15 / $0.60 за мільйон вхідних / вихідних токенів. Для інших моделей відповідні
ціни необхідно задати явно. Ціни використовуються для оцінювання та резервування бюджету; фактична вартість береться з
відповіді API. Після зміни тарифів налаштування потрібно оновити. Обрана модель має підтримувати JSON-відповіді й виклик
інструментів.

`NOVELKA_TARGET_USD_PER_5000` впливає лише на попередню оцінку глави та `job_metrics.target_usd`.
Воно не підміняє фактичну ціну OpenRouter і не змінює резерв окремих AI-викликів.

Для `resume` використовуйте ті самі налаштування моделей, що й у початковому запуску, якщо не хочете свідомо змінити
модель незавершених етапів.

## Словник і контекст

Словник окремий для кожної новели. Зберігаються японське написання, читання, український відповідник, псевдоніми, стать,
факти та їхня певність і глава-джерело. Невідома стать лишається `unknown`. У `facts` ШІ має вказувати доказ і блок
оригіналу.

Автоматичний аналіз додає нові записи. Зміни вже наявних записів зберігаються як пропозиції для перегляду; вони не
перезаписують канонічний запис автоматично. Це стосується й уточнення раніше невідомої статі. Ручні записи мають
пріоритет.

```sh
./novelka glossary n2267be
./novelka glossary n2267be --proposals
./novelka glossary n2267be --file examples/glossary.json
```

Файл — масив записів, які об'єднуються зі словником за `key` та отримують `manual=true`. Приклад у
`examples/glossary.json` синтетичний; замініть його фактами вашої новели.

У запит передається добірка до 3000 токенів `o200k_base`: згадані імена, псевдоніми, терміни й пов'язані записи. Модель
може викликати `dictionary_search`, що повертає до 1500 токенів за виклик. Ліміт — 6 інструментальних звернень і 4
запити моделі на один етап сегмента. Пошук лексичний; векторного індексу поки немає. Повний словник не надсилається.

Кожен виклик зберігає точний запит із добіркою словника й відповідями інструмента, версію словника та версію/хеш
інструкцій. Зміна використаного запису позначає залежні завдання як `needs-review`. Нові записи не роблять попередні
глави застарілими. Такі глави можна перевірити командою `proofread`, а частково перекладені — перезапустити через
`translate --force`.

При перекладі окремої пізньої глави попередні глави не аналізуються за гроші автоматично. Використовуються наявний
словник, доступний короткий контекст попередньої завершеної глави та сусідніх сегментів. Нестача контексту може
знижувати якість.

## Витрати та відновлення

Ціль якості — **$0.10 на 5000 токенів оригіналу** за аналіз, переклад і вичитку разом. Це не обіцянка фактичної ціни.
Токени оригіналу рахуються локально токенізатором `o200k_base` й разом із цільовою ціною зберігаються в `job_metrics`.
Для інших сімейств моделей цей показник залишається спільною порівняльною метрикою, а не їхнім точним білінгом.

Перед кожним HTTP-запитом зберігається й показується консервативний резерв: оцінка входу за UTF-8-байтами та максимум
8192 вихідних токенів. Тому `--budget-usd` може зупинити процес раніше фактичного вичерпання коштів. Це бюджет **нових
запитів поточного запуску**, спільний для діапазону; виконані раніше запити не списуються з нього повторно. Якщо API не
повернуло фактичної ціни, для контролю бюджету залишається резерв.

Таблиця `ai_calls` зберігає оцінку, фактичну ціну або NULL, джерело ціни, вхідні/вихідні/кешовані токени, модель,
провайдера, етап, сегмент, ID відповіді, тривалість і стан кожної спроби. NULL означає «невідомо», не нуль.
`costs --details` придатний для подальшого аналізу. У базі також зберігаються повні запити та відповіді; ключ API до них
не записується.

Відповідь моделі зберігається до застосування її результату. Повторний запуск із тим самим запитом може використати
збережену відповідь. Зміни словника після аналізу й контрольна точка цього етапу записуються транзакційно.

Після тайм-ауту, обриву з'єднання або серверної помилки результат запиту може бути невідомим: провайдер міг уже виконати
його. Автоматичного платного повтору немає. Після перевірки журналу можна явно дозволити повтор:

```sh
./novelka resume JOB_ID --retry-uncertain
```

Для HTTP 429 є до трьох спроб. Некоректна структура або обрізана відповідь не позначаються завершеними. Якщо збережена
відповідь некоректна, створіть нову версію через `translate --force`; це нові витрати. Довгий одиночний абзац, що
перевищує межу сегмента, наразі спричиняє зрозумілу помилку — можна збільшити `NOVELKA_SEGMENT_CHARS` у межах
можливостей моделі.

## Перевірки

```sh
./gradlew test                     # Парсер, сегментація, словник, pipeline, mock HTTP, HTML/EPUB
./gradlew :core:liveSourceTest     # Реальний Syosetu: метадані та одна глава; без ШІ
./gradlew :core:integrationTest    # Реальний тимчасовий PostgreSQL + mock HTTP
```

Інтеграційні тести піднімають PostgreSQL через embedded-postgres без Docker.
В обмеженому середовищі запуск PostgreSQL або локального mock HTTP може бути заборонений.
Якщо старий Gradle daemon успадкував обмеження, спробуйте
`./gradlew --no-daemon :core:integrationTest` у звичайному терміналі.
Читайте stderr initdb для точної причини. Інтеграційні тести не входять у звичайний test
і не приховують збій пропуском. [Детальніше про перевірки](doc/development.md).

Платних викликів OpenRouter у тестах немає. Літературну якість та реальну ціну ще потрібно оцінити на вибраних вами
главах. Автоматична структурна перевірка не гарантує відсутності смислових помилок.

## Джерела та подальші етапи

- [Syosetu metadata API](https://dev.syosetu.com/man/api/): метадані; текст отримується з HTML глав.
- [OpenRouter API](https://openrouter.ai/docs/quickstart): виклики моделей.
- [GPT-4o-mini](https://openrouter.ai/openai/gpt-4o-mini): початковий кандидат і тарифні орієнтири.

Наступні етапи: веб API + React-читалка; облікові записи й бібліотеки; приватні правки та їх редакторське погодження;
окремо монетизація й опційні ілюстрації. Їх у поточному CLI немає.

## Імпорт наданого тексту

`./novelka import-text n0022gd --chapter 1 --file /absolute/path/chapter.txt` зберігає наданий UTF-8 текст без
завантаження тексту із сайту. Спочатку імпортуйте метадані командою `import URL` без діапазону. Перший непорожній рядок
файлу — заголовок, наступні непорожні рядки — блоки тексту. Номер глави — позиція епізоду на сайті, тому пролог `0000`
має номер `1`.

CLI запускає JVM із часовим поясом UTC, щоб не залежати від застарілих системних назв часових поясів при підключенні до
PostgreSQL.

## Результати першого пробного запуску

Для наданого користувачем прологу перевіряємо GPT-4.1-mini після того, як GPT-4o-mini пропустила блоки й частини речень.
Вихід перекладу та вичитки тепер використовує сувору JSON Schema з обов’язковим полем для кожного ID блока. Некоректні
пропозиції словника зберігаються для перегляду, не потрапляючи до канонічного словника. Читання імен не слід вважати
встановленим лише за кандзі.

Management API keys OpenRouter не підходять для генерації. Для цього тесту звичайний ключ з обмеженням $0.10 збережено в
ігнорованому файлі `.env.translation.local`; `.env.local` залишено без змін. Обидва файли містять секрети й не входять у
репозиторій.
